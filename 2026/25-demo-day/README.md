# Session 25 — Demo Day

## What We're Learning Today

Demo Day is where you showcase what you've built. Present your capstone project, explain your code, receive feedback, and learn about next steps in your React journey.

## Prerequisites

- Sessions 01-24 completed
- Capstone deployed and working
- 3-minute presentation prepared

## Concepts

### 1. Demo Day Format

Each student gets:
- **3 minutes** to demo their app
- **2 minutes** for questions/code review
- **Total: 5 minutes per student**

### 2. What to Present

**Structure your demo:**

1. **The Problem (30 seconds)**
   - What does your app do?
   - What API did you use?
   - Who is the target user?

2. **Live Demo (1.5 minutes)**
   - Show the main user flow
   - Highlight 2-3 key features
   - Show it working on mobile (if responsive)

3. **Code Walkthrough (1 minute)**
   - Show your favorite component
   - Explain one interesting technical decision
   - Show how you handled state management

4. **What You Learned (30 seconds)**
   - Hardest bug you fixed
   - What you'd improve with more time

### 3. Demo Day Rubric

| Criteria | Points | Description |
|----------|--------|-------------|
| **Functionality** | 25 | Does it meet the feature checklist? (2 routes, API, context, responsive, deployed, 2 tests) |
| **Code Organization** | 25 | Clean folder structure, meaningful names, separated concerns |
| **UI Polish** | 25 | Consistent styling, responsive, loading/error states |
| **Code Understanding** | 25 | Can explain decisions, knows what every line does |

### 4. Feature Checklist Verification

Make sure you can demonstrate each:

- [ ] **2+ routes** — Show navigating between pages
- [ ] **API with loading/error** — Show loading state, show data
- [ ] **Context/global state** — Show state shared across components
- [ ] **Responsive** — Show on mobile viewport
- [ ] **Deployed** — Live on GitHub Pages
- [ ] **2+ tests** — Run `npm run test` and show results

### 5. Explaining Your Code

**Do:**
- Explain WHY you made certain decisions
- Show how data flows through your app
- Talk about trade-offs you considered
- Mention what you'd do differently

**Don't:**
- Read code line by line
- Rush through without explaining
- Say "I don't know" — say "I learned about X but would research Y further"
- Blame opencode — take credit for your learning

### 6. Handling Questions

**Common questions and how to answer:**

Q: "Why did you choose this API?"
> A: "I chose [API] because [reason]. It was free, CORS-friendly, and had good documentation."

Q: "What was the hardest part?"
> A: "The hardest part was [specific challenge]. I solved it by [solution]."

Q: "What would you add with more time?"
> A: "I'd add [feature] because [reason]. I'd also improve [area]."

Q: "How did opencode help?"
> A: "opencode helped me with [specific task]. But I made sure I understood every line of code it generated."

### 7. Code Review Tips

When reviewing others' code:
- Ask about interesting patterns
- Suggest improvements constructively
- Share what you learned from their approach
- Be encouraging — everyone built something from scratch!

## Step-by-Step Walkthrough

1. **Before Demo Day:**
   - Run all tests and verify they pass
   - Test all routes on the deployed site
   - Prepare your 3-minute presentation
   - Practice explaining your code out loud
   - Make sure your repo is clean (no uncommitted changes)

2. **During Demo Day:**
   - Start with the problem, not the code
   - Demo the main user flow first
   - Show your favorite feature
   - Be honest about challenges

3. **After Demo Day:**
   - Review feedback and notes
   - Continue improving your capstone
   - Start your next project
   - Share your work on social media

## Try It Yourself

1. **Easy:** Write a 3-sentence description of your app for your portfolio.

2. **Medium:** Record yourself doing a 3-minute demo. Watch it back. What can be clearer?

3. **Challenge:** Add one final polish feature based on the rubric criteria.

## Common Mistakes & How to Fix Them

- **Demo fails** — Have a backup (screenshot, video). Test before you present
- **Running over time** — Practice with a timer. Cut non-essential features from the demo
- **Not understanding your code** — If you used opencode, make sure you can explain every line
- **Being too modest** — You built a full React app from scratch. Be proud!
